## Always-on invariants
- Modular monolith: dependencies point down only, `interfaces -> application -> domains -> core`; skipping a layer downward is legal (`interfaces -> <domain>.public` for a genuine single-domain request), skipping sideways or upward is not.
- Domains never import one another; external domain contract is `public.py` + immutable DTO/value objects.
- Cross-domain flows live in `application/`.
- Outbound vendor capabilities are ports on `application/<a>/ports.py` implemented by `integrations/<v>/outbound`; only `config/` binds a concrete adapter and it injects into entry points — `interfaces`/`tasks` never import `config/*` or `integrations/*` (a webhook may use `integrations/<v>/protocol` only).
- PostgreSQL is commercial source of truth; Redis is disposable acceleration.
- Money is `Money` = integer minor units + an **explicit** currency: exact, never `float`, never an inferred currency, arithmetic and ordering **currency-scoped** (equality total, ordered comparison same-currency only), signedness a field invariant not a primitive one, every fractional conversion naming an explicit `RoundingPolicy` with **no default**, and no implicit FX. Public locators are `PublicId` (UUIDv7) — a locator, never a permission, never a version, never an ordering key; message identity is the distinct type `EventId` over the same value space.
- Actor-scoped authorization, durable idempotency, DB constraints, immutable order snapshots.
- **Command idempotency is PostgreSQL-canonical and ACID-coupled**: `UNIQUE (scope, key)` + principal binding + a semantic request fingerprint; for a command scope whose protected effect is **one local ACID transaction**, the claim, the effect and the replayable completion commit **together**, a rollback leaves **no** durable claim (no `processing`, no `failed`), and Redis is disposable anti-storm only. **Provider I/O is never that effect** — a provider call happens strictly post-commit under its own provider idempotency key and reconciliation (ADR-0007 §3, ADR-0010), and a scope *name* like `payment.initialize` proves nothing about shape. Replay is principal-scoped and returns a **bounded semantic** result (never a stored raw response); expiry ends the replay promise, so a permanent business rule lives in a domain `UNIQUE`/state machine, not in a retention-limited row. It never replaces Inbox/`EventId` identity, provider `external_event_id` dedupe or an outbound provider idempotency key.
- **Primary-only at launch**: the application sends **no** read traffic to a PostgreSQL replica; a global "all SELECT → replica" router is forbidden **permanently**. An **HA standby is a different concept** (backups/PITR/failover; never an application read target). A future replica is an evidence-gated, **per-read-path** opt-in with read-your-own-writes, lag safety and fallback-to-primary; correctness reads (placement, inventory, pricing-for-write, payments, idempotency, actor/security, Outbox/Inbox, webhook ingest, the item 12 projection builder) are never replica candidates, whatever the gate does.
- Order placement is `application/checkout.place_order`: one local `atomic()` for every durable write, idempotency claimed and completed inside it, provider payment strictly post-commit and owned by `application/payments_gateway`.
- Outbox/Inbox: typed + versioned + idempotent + trace-propagating. Only a **registered** `(event_type, schema_version)` may be emitted; a published version is immutable; consumers support exact versions; unknown/invalid → durable quarantine + alert, never a silent fallback and never marked HANDLED.
- Async trace/causality is a **closed four-field envelope extension** — `trace_id`, `producer_span_id`, `request_id`, `causation_event_id` — captured into the durable Outbox record inside the business transaction, write-once, absence-tolerant, never payload and never bumping `schema_version`. The durable row (not broker headers, not a live process) is the source of truth; each consumer delivery gets its own processing span; a replay keeps the message's lineage immutable and runs in a **new** trace that links to it. Trace metadata never decides authorization, identity, money, idempotency, ordering or routing, and no observability outage or sampling decision changes a business outcome.
- Async transport is partitioned into **logical failure domains** with reserved capacity for critical ones; a domain is assigned **per consumer**, never per message version, and never by the producer; queue identity is transport metadata and a routing change never bumps `schema_version`; priority is not isolation; no queue retries forever; contract **quarantine** ≠ operational **dead-letter**, both canonically durable in PostgreSQL with a per-domain terminal namespace; the unit of failure, terminal identity and replay is a **consumer delivery** — replay is explicit, authorised, identity-preserving, scoped to the failed consumer, and never rebroadcasts to a sibling that already succeeded.
- Storefront hot path: `ProductListingProjection -> DTO -> HTML/JSON`; the projection is a derived serving read model owned by `application/storefront`, never checkout truth, fully rebuildable from OLTP, and a miss never falls back to cross-domain joins in the request.
- Projection writes converge by **compare-and-set, not by source ordering**: a trigger is a dirty-identity signal, the writer observes the row's `projection_revision` **before** every source read's *visibility point*, rebuilds the whole candidate from **authoritative** current state through `<domain>.public` batch selectors (never a cache entry, never a lagging replica, never a snapshot opened earlier), and commits only if the token is still equal (equality only — never `>`). A guard miss discards the candidate whole and rebuilds; an unchanged candidate writes nothing at all. Token non-reuse is scoped to a projection generation; a reset is legal only behind a fence that invalidates every prior observation, so the projection stays fully disposable. No producer supplies a version, no domain learns it is projected, rebuild/reconciliation/replay use the same protocol, and there is no force-write path.
- **No analytics domain in MVP.** `popularity_score` is derived storefront ranking state owned by `application/storefront`, computed only from existing first-party business facts (successful sales, favorites) — never from page views, clickstream or any behavioural collection, none of which exists. Every source contribution is a **query over the owner's current state, never an accumulator**, so removal, refund and event-history deletion are correct for free. A source is enabled only when its owner exists; a non-enabled source is a policy term, never a stub; an *enabled-but-failing* source is a technical fault, never a silent neutral.
- **MVP cuts features, never invariants.** No MVP module may import, reference, probe for or branch on a `LATER` module, and absence is expressed by the **absence of a call** — never by an empty package, a null/no-op adapter, a `try: import` fallback, an `INSTALLED_APPS` probe or a settings-gated unreachable path. A mechanism stays FOUNDATION even when its consumer is later (event versioning without analytics events, failure-domain machinery without `ext.crm`); a frozen definition is never a launch commitment (a defined queue is provisioned only when its workload is enabled). Launch cut per module: item 14.
- Query budgets/N+1 checks are CI invariants.
